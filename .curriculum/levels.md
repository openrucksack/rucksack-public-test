# Levels and areas

This file is the source; `skills/teach/references/levels.md` in the template is its offline copy. The per-cell observable standards (six areas by five levels) are still to be written from the research of 10 October 2026; the table below is the summary.

Capability is a profile, not a badge: six areas, each at a level from one to five,
each level earned by something the person actually did and checked. A person can be
level three at documents and level one at money. "Not yet looked at" is normal.

## The six areas

| Area | The question it answers |
|---|---|
| Choosing | Do I know what AI is good for, when not to use it, and which tool? |
| Asking | Can I give it what it needs and refine when it misses? |
| Checking | Do I judge the result against evidence, in proportion to the risk? |
| Staying safe | Do I protect people and data, and understand permissions and consequences? |
| Keeping it running | Do I keep usable files, routines and instructions, delegate within limits, and recover when it fails? |
| Growing | Do I adapt as tools change, keep my own judgement, and help someone else? |

## The five levels

| Level | Name | What changes | In rucksack terms |
|---|---|---|---|
| 1 | First safe use | One real low-risk task, a check against a known fact, a boundary written down, a result saved and found again | The rucksack exists and loads; USER.md has a boundary; one memory note |
| 2 | Working with it | Chooses tasks unaided; gives examples and constraints; asks for clarification; opens the sources behind a claim; has compared two tools or modes on the same task; checks in proportion to risk | SOUL.md written; a reusable brief in `skills/`; the model-choosing rule in FLEET.md from a real comparison; a claim ledger in `learn/evidence/` |
| 3 | Repeatable | Keeps a concise context pack; restarts a task cleanly in a fresh chat; works in real files; runs one routine on three inputs including an awkward one, with a manual fallback and the checking time measured | `projects/` in use; the first routine written; the tidy run; MEMORY.md curated once |
| 4 | Trusting it with tools | Maps what a tool can read, change, send and delete; writes a bounded delegation; dry-runs before changes; has seen a hidden instruction in a document and written a rule for it; can stop an agent and restore a test folder | A write path connected (the GitHub connector or a folder agent) and its permission map in `learn/evidence/`; the injection test done on a `memory/` note; `vault/` used for a dry run |
| 5 | Running the show | Runs a scheduled routine with monitoring, an owner, a failure signal and a cost ceiling, or has decided on purpose not to; reruns a small personal benchmark monthly; moves instructions to a second tool without loss; helps someone else; retires what is not worth it | `HEARTBEAT.md` has a live line; `learn/evidence/benchmark.md` exists; the rucksack has been opened in a second vendor's app with nothing lost; a routine has been retired with the reason written |

The observable standards per area per level are still to be written (see the top of this
file). A tool failure, a paid feature the person does not have, or a decision not to automate is
never evidence of a lower level.
